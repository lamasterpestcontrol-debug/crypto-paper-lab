## 2. 首版的临时测试参数

这些是为了验证流程而设置的默认值，不是对用户此前投资参数的复述，也不是买入建议。

| 参数 | 首版默认值 |
|---|---|
| 市场 | BTC/USD、ETH/USD、XRP/USD |
| 行情源 | Kraken 公开 OHLC 和买卖价差接口；不需要交易所账户密钥 |
| 扫描间隔 | 目标每 60 秒一轮，网络故障时记录暂停，不伪造数据 |
| 信号周期 | 15 分钟，仅使用已结束的 K 线 |
| 虚拟初始资金 | 10,000 美元，不从任何真实账户扣款 |
| 单币资金上限 | 初始资金的 10%，三币合计最多初始资金的 30% |
| 买入规则 | 最近 5 根均价超过 20 根均价的 1.001 倍，且最新已结束 K 线收盘价突破此前 20 根收盘价高点 |
| 趋势卖出 | 在新的已结束 K 线上，5 根均价低于 20 根均价 |
| 其他卖出规则 | 模拟净收益率触及 -3% 止损、+6% 止盈；仅在有效报价下执行 |
| 全账户熔断 | 相对已记录净值高点回撤达到 10%，停止开仓并在有效报价下退出；重启不自动解除 |
| 手续费假设 | 每边 0.4%，不是经过核实的个人交易所费率 |
| 滑点假设 | 每边额外不利滑点 0.1%，另计实际观察到的买卖价差 |
| 净值计算 | 按卖一侧报价扣除假设滑点及退出费用进行估值 |
| 对照组 | 相同起点、相同成本假设的等权买入持有；满仓对照与策略低仓位的风险敞口不同，不能直接把差异都称为策略优势 |
| 重复下单保护 | 同币同一根信号 K 线不重复开仓，落库与交易事件采用同一事务 |
| 异常处理 | 缺失、过期、乱序、未结束 K 线、交叉/过宽价差、数据不全时暂停整轮模拟交易 |

止损是定时观察后的模拟成交，不保证能按止损价成交。程序没有订单队列、完整深度、市场冲击模型，也不模拟税款。小样本收益或胜率不能证明策略盈利。此版本为固定规则基线，不自动调参，不自动切换实盘。

## 3. 先上传代码：最少的软件操作

目标仓库：`lamasterpestcontrol-debug/crypto-paper-lab`。

1. 将交付的 ZIP 解压，打开解压后的目录。
2. 在 GitHub 网页打开上面的现有仓库，选择 **Add file → Upload files**。
3. 把解压后的文件上传到仓库最外层。**不要只上传 ZIP，也不要把文件套在另一层目录里。**
4. 检查最外层能看到 `paperlab.py`、`test_paperlab.py`、`Dockerfile`、`railway.json`，然后提交变更；若按仓库规则创建了分支，完成正常审核合并后再部署对应分支。

所有文件均为代码、说明或无密钥测试报告；包内不包含交易所密钥、GitHub token、真实账户密码或部署密码。

当前普通 ChatGPT GitHub 连接是只读入口，不能代替用户的写权限。手动提交是用户使用自己的合法仓库权限，不是提升或绕过连接器权限。没有必要为存放这份代码购买 GitHub Pro。

### 存储条件

永久模拟记账需要合法可用的持久化数据盘，挂载点是 `/data`。此前自动创建数据盘的请求受到工具安全检查拦截；本交付不包含绕过该检查的操作。需要经平台的正常授权/审批流程解决存储条件，再完成上线验收。

在 Railway 环境中，程序同时检查平台提供的挂载变量和真实挂载点。仅创建一个叫 `/data` 的普通临时目录，不会被认定为持久化成功。没有满足条件时，网页可显示诊断，但模拟下单保持暂停。

不要手工伪造 `RAILWAY_VOLUME_MOUNT_PATH` 或 `RAILWAY_ENVIRONMENT_ID` 来跳过检查；这两个运行环境变量由平台提供。

### 应用变量

在正常授权的 Railway 配置入口设置；源码中不保存密码：

| 名称 | 值 |
|---|---|
| MODE | PAPER_ONLY |
| DATA_DIR | /data |
| PORT | 8080 |
| DASHBOARD_PASSWORD | 新生成的随机密码，至少 16 字符，建议 24 字符以上，不包含冒号 |

**不要复用之前聊天中出现过的密码，不要把部署密码上传 GitHub，不需要把密码发给我。**
网页登录用户名为 `viewer`，密码为你设置的 `DASHBOARD_PASSWORD`。使用 Railway 提供的 HTTPS 地址打开网页，不通过不加密的公共 HTTP 发送登录信息。

## 5. 完成任务的验收条件

必须区分基础镜像部署成功、程序启动成功、行情可用、模拟交易正确和策略盈利，不能互相替代。

1. **构建**：本份源码构建通过，37 项测试在目标镜像内再次通过。
2. **程序身份**：部署状态为 SUCCESS，日志出现 `APPLICATION_STARTED` 且版本正确；`/healthz` 返回 `paper-baseline-1.0.0`。仅看到 `Starting Container` 不够。
3. **行情和存储**：`/readyz` 返回 200；有效行情时间持续更新；`storage_ready=true`；至少观察连续两轮 `SCAN_OK`，而不只是一次 HTTP 成功。
4. **模拟记录**：有条件时产生可复算的虚拟成交；没有信号时保留 WAIT，不为了展示交易而强行买入。CSV 能导出累计成交，净值已扣成本。
5. **重启恢复**：正常重启后虚拟余额、持仓、累计交易与扫描计数保留，不重复开仓、不自动清零。
6. **手机查看**：HTTPS 页面可登录，显示净值、回撤、扫描次数、异常次数和记录；这是网页查看，不等于已经设置 ChatGPT 主动推送提醒。

`/healthz` 只用于确认程序能响应；`/readyz` 才包含最近完整扫描与存储检查。风险熔断后行情与记录仍可正常，但不会再开新仓。

## 6. 记录和维护

- SQLite 文件位于 `/data/paperlab.sqlite3`。此版本只允许一个运行副本。
- 累计交易不自动删除；逐轮扫描保留最近 10,080 条（正常每分钟一轮时约 7 天）；每日扫描/异常计数及累计计数继续保留。
- 无自动数据库异地备份。CSV 是交易导出，不是完整数据库备份，不能代替持仓和状态备份。
- 更改策略、费用或版本时会检查配置指纹，不允许在原账本中静默改规则。需要明确迁移，或使用新的独立运行目录并保留旧记录。
- 模拟账户启动后的盈亏只是前向观察结果。验证稳定性后，再扩展早期项目发现、真实用途/收入核实、消息通知等模块，不应将未实现模块描述为已经上线。
- 本地运行支持 Linux/macOS；Windows 可使用经正常配置的 Linux/Docker 环境。你不需要在自己的电脑上持续运行，正式部署目标仍为 Railway。
